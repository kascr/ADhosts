# ADhosts

ADhosts 是使用 Magisk、KernelSU 或 APatch 模块管理 Android Hosts 的应用，支持订阅源、手动规则、规则合并与 DNS 切换。

## 使用要求

- Android 10 或更高版本（API 29+）
- 可用的 Root 管理器及 Root 授权
- KernelSU 3+ 和 APatch 11219+ 需要启用兼容的 MetaModule；安装或更新挂载模块后需要重启

## 主要功能

- 为每个订阅保存独立规则文件，启停时移动文件并重建 Hosts
- 下载、合并和去重多个 Hosts 订阅，手动规则优先
- 使用 MT 管理器编辑独立的手动规则，保存返回后校验并合并
- 导入、导出订阅与手动规则
- 开启或关闭 Hosts 拦截，以及选择 DNS
- 域名查询同时显示本机 IPv4/IPv6 解析、运行中的 Hosts 地址和规则来源
- 在“关于”页检查 GitHub 正式发布版，下载 APK 并通过 Root 安装

## 编辑手动规则

点击 Hosts 页的“添加”，在弹窗中选择“手动添加”，使用 MT 管理器编辑规则副本。目前支持正式版（`bin.mt.plus`）和共存/测试版（`bin.mt.plus.canary`）；同时安装时可选择版本，未安装时可前往[官方下载页](https://mt.cc/download/)。

编辑文件预置当前应用语言的注释说明和示例。以 `#` 开始的注释、行尾注释以及空行不参与合并和计数；示例默认也是注释。只填写域名时使用 `0.0.0.0`，也可填写完整的 IPv4/IPv6 Hosts 规则。

在 MT 保存后返回 ADhosts，合法修改会自动合并；Hosts 已启用时同步应用。格式错误会提示行号并保留原规则，清空手动规则需要确认。编辑副本和会话保存在应用私有目录，应用进程被结束后仍可继续处理；手动规则继续参与备份和恢复。

保存中的副本不会被导入；保存中断或副本丢失时，可重新打开检查并保存，或放弃副本。取消示例行的注释后，规则会保留到后续编辑中。

## Root 与 DNS

应用通过当前提供 `su` 的管理器选择安装命令。实时更新在系统挂载命名空间中应用；已有 Hosts 挂载会保留原文件节点并更新内容，避免旧规则残留、挂载源被删除或连续增加挂载。首次建立 KernelSU 挂载时使用 `KSU` 来源标记。界面通过运行中的 Hosts 内容核对是否生效。

订阅开关、更新应用和规则恢复会共同保存配置、缓存、快照及 Root 文件的恢复记录；操作中断后，下次启动会恢复至操作前的状态。

DNS 选择沿用原有的 `net.dns*` 属性方式，不修改系统私人 DNS 的模式或域名。“恢复默认”或关闭拦截会清空这些 DNS 属性。

“域名查询”合并了原来的规则查询和网络查找。查询使用本机系统解析路径，与当前运行的 Hosts 进行对照，不再绕过 Hosts 查询远端 DNS。解析到拦截地址、IPv4/IPv6 结果不一致、规则尚未生效、无法解析和超时会分别显示；Ping 无回应不代表拦截成功，采用独立 DNS 的应用可能得到不同结果。

## 构建

使用 JDK 17 和 Android SDK 构建：

```text
./gradlew assembleDebug
```
